| S2 | IP 纯净度数据来源 | 允许依赖外部 API：经节点取 IP（`cdn-cgi/trace` → `ipwho.is` → `api.myip.com`），再把 IP 直连交给 `ip-api.com` 判 hosting/proxy/mobile/ASN | 已实现 |
| S3 | 纯净度权重 | 住宅/移动 100、机房 55、被判定代理 20、地区虚标 -25；作为独立维度权重 0.10，其余平台按比例让出，`purity_weight` 进 `scores.json` | 已实现 |
| S4 | 地区偏好怎么落地 | 名称识别地区（国旗/中英文），偏好地区 +5 加成；同时用实际国家校验，虚标通过 S3 扣分而不是加成 | 已实现 |
| S5 | 「每 5 分钟测选中节点」 | `watchdog.py` 对选中节点检查 3 个不同目标。至少半数失败时，按同一批目标检查组内候选节点，通过内核 API 固定到首个健康候选并读回确认 | 已实现 |
| S6 | 周期任务载体 | 容器内两个独立循环（巡检 300s、完整事务 21600s），不用 crontab；间隔全部来自环境变量 | 已实现 |
| S7 | UI | 定制 Zashboard 提供节点控制与评分/纯净度/巡检诊断，shell 提供只读诊断快照 | 已实现 |
| S8 | 纯净度接口不可用 | 快照超过 12h 即忽略，评分退化为纯连通性；不阻塞刷新事务 | 已实现 |
| S9 | 没测到纯净度的节点怎么算 | 按 `MIHOMO_PURITY_MISSING`（默认 40）计，不按满分计：不测不等于干净，避免缺数据占便宜 | 已实现 |
